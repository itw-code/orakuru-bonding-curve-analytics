Orakuru bonding-curve analytics

Proof notes for an on-chain data analyst application. This page only restates what is in the public repo and what test_pipeline.py prints on its synthetic fixture. It is not a live Orakuru dashboard.

Repo: itw-code/orakuru-bonding-curve-analytics (public, branch main, commit 4dcd3f1).

What the analysis is

A dbt-style pipeline (staging views, intermediate state, Kimball marts) plus three Dune SQL files. It models three things for a bonding-curve launchpad:

  • Curve state and graduation. Virtual reserves, spot price, and fill percent capped at 100 when collected base reaches the graduation threshold. Status becomes GRADUATED at that cap. See int_bonding_curve_state.sql and 01_bonding_curve_realtime_monitor.sql.
  • Sniper clustering. A wallet is tagged SNIPER when its first trade is within 2 blocks of curve creation. See int_wallet_clustering.sql and 02_wallet_clustering_and_snipers.sql.
  • Token velocity. Daily V = base volume / implied market cap, plus turnover (tokens traded / supply). Tiers in int_token_velocity.sql: HYPER_VELOCITY at V ≥ 2, HEALTHY_CIRCULATION at V ≥ 0.5, MODERATE_VELOCITY at V ≥ 0.1, otherwise STAGNANT_LIQUIDITY. Query: 03_token_velocity_and_health.sql.

What was actually checked

No Dune extract, notebook, or saved query result is committed. The only executed result in the repo is test_pipeline.py. It loads a small synthetic book (two curves, nine swaps) into in-memory DuckDB and asserts five invariants. Running that file printed the rows below, and all five assertions passed.

CheckPrinted resultHow to read it
Graduation 0xnova fill 100.0, status GRADUATED On this fixture the curve is treated as fully filled and graduated. This is not a count of real Orakuru launches.
Snipers 0xsniper_1 and 0xsniper_2: is_sniper = 1, cohort SNIPER Both addresses buy in the first two blocks after creation, so the rule flags them. Later wallets in the same fixture are not in this printout.
Wallet segment 0xwhale_1 → WHALE Segment label from dim_wallets for that fixture address. Not a measured share of real supply.
Velocity 0xphantom: V 0.3385, turnover 46.0, MODERATE_VELOCITY
0xnova: V 0.39, turnover 79.0, MODERATE_VELOCITY		 Both sit between 0.1 and 0.5, so the model’s moderate tier, not the “healthy” band (0.5–2) described in the README.
Mart grain 7 distinct traders in the raw swaps, 7 rows in dim_wallets The wallet dimension does not fan out on this fixture.

Reproduce: python test_pipeline.py (needs DuckDB). The script’s own header says the trades are synthetic.
